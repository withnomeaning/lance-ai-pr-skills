# 汽车危机回应通稿类型卡

> 本文件在稿件类型为汽车行业危机回应时读取。区别于常规新车通稿，更重事实确认、责任界定、补救动作。
> 读取后必须同时执行 `writing-rules.md` 和 `final-review.md`。

## 触发条件

主线是"出了什么事，品牌怎么回应"。适用于产品召回、安全事故、定价争议回应、智驾事故、排放合规问题。

**与 `auto-launch.md` 的边界**：
- 主线是发布/上市/活动 → 走 `auto-launch.md`
- 主线是回应事故/争议/召回 → 走本文件

---

## 危机通稿的核心原则

1. **事实先于态度**：先说明发生了什么（时间、车型、数量、原因），再表态
2. **动作大于承诺**：写"已启动召回""已暂停交付"，不要只写"深感抱歉"
3. **口径一致**：通稿、官网、客服、经销商必须统一，本文件产出即为唯一对外口径
4. **不猜测不预判**：事故原因待查就说待查，不推测；责任人待认定就说配合调查

---

## 小类路由

### 小类一：产品召回

**适用**：主动召回、被动召回（市监局责令）、OTA召回。

**标题公式**：品牌 + 召回动作 + 车型/批次/数量 + 原因简述 + 解决方式

**标题示例**：
- XX品牌召回XX辆XX车型，涉及XX部件安全隐患
- XX品牌主动召回XX批次车型，免费更换XX总成
- XX品牌发起OTA召回，升级XX系统软件以消除XX风险

**写作结构公式**：
召回决定 → 涉及车型/数量/生产日期 → 缺陷描述 → 可能后果（客观描述）→ 解决方案（免费/时间/渠道）→ 用户须知。导语第一句写决定依据（向市监局备案/主动召回）、涉及车型和数量；正文写缺陷和风险（客观不渲染），再写免费维修方案和预约渠道；结尾写用户注意事项和客服渠道。必须包含市监局缺陷产品管理中心备案信息。

**小类失败条件**：
- 不写缺陷具体是什么，只笼统说"安全隐患"
- 不写涉及数量和批次，或隐瞒真实规模
- 把强制性召回包装成"免费升级""关怀活动""售后服务"

---

### 小类二：安全事故声明

**适用**：用户事故、测试事故、智驾事故。

**标题公式**：品牌 + 对XX事件的声明/关于XX情况的说明 + 核心动作

**标题示例**：
- XX品牌关于XX用户车辆事故的声明
- XX品牌关于XX事件的情况说明

**写作结构公式**：
事件确认 → 已知事实（时间、地点、车型、目前掌握的情况）→ 已采取动作（配合调查/成立专项组/联系用户）→ 后续信息发布渠道。导语第一句确认事件、表达关切；正文只写已核实的事实，不确定的写"正在核实""配合调查"；结尾写下一步信息发布渠道。

**小类失败条件**：
- 在调查结果出来前预判责任
- 不写已采取的具体动作，只表态
- 暗示或明示"用户操作不当"而未核实

---

### 小类三：定价/权益争议回应

**适用**：降价维权、权益变更争议、交付延期用户投诉。

**标题公式**：品牌 + 关于XX事项的说明/致用户信 + 核心措施

**写作结构公式**：
致歉/说明 → 争议的具体问题 → 调整措施/补救方案 → 生效时间和覆盖范围 → 后续沟通渠道。导语直接面对争议，不回避；正文先写具体问题是什么，再写补救方案（必须是具体可执行的，不是态度表态），然后写覆盖范围和生效时间。

**小类失败条件**：
- 回避争议核心问题，只道歉不给方案
- 补救方案模糊（"将优化""将考虑"）
- 区分新旧用户待遇，制造新的对立

---

## 完整稿准入（危机稿特殊要求）

- 必须包含：① 事实确认（发生了什么）② 已采取动作 ③ 用户须知/受影响范围 ④ 信息发布/客服渠道
- 不得出现：推卸责任暗示、事实猜测、隐瞒关键信息
- 法律风险点须经法务审核（本文件只做公关判断，不替代法律意见）

---

## 类型失败条件

- 回应回避核心事实，读完后不知出了什么事
- 态度大于动作，道歉占比超过事实和措施
- 暗示用户/第三方责任而未核实
- 把危机包装成营销（"这次召回体现了我们的责任感"）
- 通稿与客服/经销商口径不一致
